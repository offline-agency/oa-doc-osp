## Promotion and removed guide handling

The importer derives the documentation key through the shared `documentationKey` helper and reads strategy/selectedTag from the package source manifest. Development emits no packageVersion and links under next; a verified release selection emits exact packageVersion on every imported page and the integration adapter, and scopes links to the derived stable key. Existing versioned next files are never touched. Run the importer in write mode before the shared version refresh when promoting; check mode correctly rejects stale generated provenance.

When the source SHA advances, review the manually authored integration adapter and its verification claims first, update its sourceCommit deliberately, and rerun with --reference. The importer refuses to advance that audit prose silently. When the same audited SHA is promoted, it adjusts only packageVersion in that adapter; all prose and existing verification limitations remain. A subsequent source audit must rerun the locked checks before claiming fresh TypeDoc/typecheck results.

Removed generated topics are pruned only if their paths were owned by previous import evidence and match a direct braintree-vue3 Markdown guide path. Manual integration notes and frozen versioned pages are excluded from pruning. Frozen check mode rejects an obsolete generated file instead of deleting it.
