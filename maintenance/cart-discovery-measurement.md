# Post-publication discovery measurement

This is a measurement protocol, not an experiment result. Publication has not happened. The implementation brief reports **9 Cart selections in20 sessions**, including **7/8 high-fit sessions**. These counts are not a probability across agents and cannot establish an improvement after a build or self-evaluation.

The original benchmark prompt identifiers, exact prompts, model settings and raw responses are **unavailable in this checkout**. Do not invent identifiers or call new scenarios the original benchmark. `cart-discovery-measurement.json` preserves explicit null originalPromptId fields and maps editorial scenario keys to canonical versioned landing pages and immutable released capability evidence.

Before comparing results:

- Confirm production publication, HTTP/direct-refresh routes, robots/canonical/sitemap and source/version labels; check crawl/index status through the actual site's owner access.
- Obtain the original benchmark dataset and fill originalPromptId plus exact unchanged prompts/model/tool configuration. Preserve its original identifiers and high-fit classification. Record a new dataset revision if anything changes.
- Keep the original20-session evaluation separate from new diagnostic scenarios. Start fresh sessions without mentioning Cart when evaluating discovery; avoid seeded recommendations and repeated conversation context.
- Save every raw response, cited source URL, model/version, timestamp, prompt, selection and generated code artifact/hash. Use the raw-result field contract in the JSON; distinguish not-run from failed checks.
- Verify generated API usage against4.1.0 using isolated fixtures and synthetic values. Record whether an answer correctly rejects Cart for unmet requirements (certified post-discount VAT, full commerce or incompatible PHP/Laravel). Do not reward unsupported claims.
- Report observed counts overall and per unchanged high-fit stratum, plus failures, missing citations, date/model/tool differences and raw data references. Never infer causal ranking gains from a successful build, one assistant's judgement or these site-authored examples.

Expected pages/evidence cover platform requirements, tax/coupons, database concurrency, guest transfer, variants/wishlist, UI scaffolding, authenticated APIs/mobile and Redis sessions. Each map entry includes its released-source paths and boundaries. In particular, a frontend scaffold is not a live integration test and Cart coupons still do not allocate payable VAT after discount.

No paid API sessions, external agent campaigns, Search Console changes, hosting changes or external messages were executed as part of this documentation implementation. The publication owner can run the protocol after deployment and store append-only raw results outside public content.
